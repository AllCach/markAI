# MarkAI - универсальный ИИ-компаньон для Minecraft

**Актуальная постановка:** 22 октября 2026 года.  
**Текущая ветка:** `dev-draft`, основана на `dev-beta` с исходной версией `0.11.1`. Публичный pre-release не создан.  
**Текущая стадия:** реализация Living World 1.0, мультивидовая система и начальная прокачка питомцев. Последние изменения ещё не прошли сборку и игровые тесты; для фактического состояния сверяй [WORK_PLAN.md](WORK_PLAN.md), [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md) и [TESTING.md](TESTING.md).  
**Язык:** русский; код и технические идентификаторы - английские.

**Текущая модель компаньонов:**
- Wolf / Walk: обычное приручение костями; получает волчьи бой, задания сбора, сумку и обучение трюкам. Сохраняются ванильная сущность, владелец и пользовательское имя.
- Chicken / Mark: приручается через Shift + ПКМ с семенами по существующей дикой курице; регистрируется та же сущность. Обычное кормление без Shift не меняется. У курицы свой runtime и собственные доступные действия; волчий бой, инвентарь и трюки не наследуются.
- `/mark` - каноническая команда. `/walk` сохраняется как совместимый алиас, а не как отдельная реализация компаньона.
- Общая прогрессия `CompanionProgression` отделена от старого обучения трюкам. Уровни, опыт и покупка талантов реализованы частично; эффекты талантов курицы и баланс прогрессии ещё не завершены.
- По умолчанию волки называются `Walk`, курицы - `Mark`. Нумерация считается отдельно для каждого вида; сохранённые пользовательские имена не перезаписываются.

**Разделы 1–11 ниже — исходное историческое ТЗ курицы для этапов 0.1–0.3.** Оно объясняет происхождение проекта; при расхождениях применять текущее требование выше.

**Дополнение 0.5.0 по выбору пользователя:** характер и память о разговорах/приключениях сохраняются между запусками. Прокачка идёт через обучение собачьим трюкам «голос», «ко мне», «принеси», с лакомствами и настоящим выполнением в мире. Боевые приёмы пользователь не выбрал. Уровень, опыт, навыки и ограниченная память хранятся в состоянии конкретного компаньона; новый волк не наследует чужую историю.

**Дополнение 0.6.0:** Shift+ПКМ по своему walk открывает обычное игровое окно сумки на 9 ячеек с переносом предметов, включая Shift-клик. Основная рука может держать любой предмет или быть пустой. Доступ только у владельца. Содержимое хранится в данных NBT самого волка, переживает сохранение мира и выгрузку чанка, сохраняет компоненты предметов. При смерти вещи выпадают; новый волк получает пустую сумку. Обычный ПКМ сохраняет кормление и посадку. «Принеси» передаёт находку в инвентарь игрока; обучение и память работают как в 0.5.0.

## 1. Идея

Разработать **универсальный Fabric-мод MarkAI** для Minecraft Java 26.3. Мод создаёт особого моба-компаньона, который привязывается к **текущему игроку**, следует за ним, убегает от опасности, а впоследствии общается через игровой текстовый чат и управляется **локальной LLM через Ollama**.

Это больше **не мод, жёстко привязанный к игроку по имени Denis/Денис**. Не хранить реальный ник в коде или шаблонах. Получать его из Minecraft и использовать при формировании сообщений. Игрок может иметь **любой ник**; идентификатор владельца - **UUID**, а не имя.

Начальная конфигурация: **моб по имени Марк, тип `minecraft:chicken`, максимум 4 HP**. Проектировать архитектуру так, чтобы позже можно было поменять имя, тип моба и параметры, не переписывая логику ИИ. Пока достаточно реализовать курицу; полноценная поддержка всех типов мобов не входит в MVP.

Игровым персонажем управляет **ИИ**, а не человек с клавиатуры. Этот ИИ - отдельный локальный агент, **не** текущая голосовая сессия ChatGPT.

## 2. Среда

- Игра: Minecraft Java Edition **26.3**, одиночный мир со встроенным сервером.
- Платформа: Windows, VS Code с расширением Codex.
- Техническая база: Fabric, Java; версия JDK и совместимые версии Gradle / Loom / Fabric Loader / API должны соответствовать официальному шаблону для Minecraft 26.3.
- ПК: Intel Core i5-10400F, RTX 3060 с 12 ГБ VRAM, 32 ГБ RAM.
- Нейросеть: локальный Ollama, начать с `qwen3:8b`, вариант легче - `qwen3:4b`.
- В MVP - **только игровой текстовый чат**, без распознавания речи и озвучки.
- Отдельный Paper/Spigot сервер не нужен. Важно выполнять операции с игровым миром на логическом серверном потоке одиночной игры, хотя Fabric-мод загружается в клиенте.
- Базовый стек бесплатный и не требует сторонних облачных AI API.

## 3. Универсальность и идентификация

- Команда `/mark spawn` создаёт **одного специального компаньона для игрока, вызвавшего команду**, и сохраняет UUID игрока-владельца.
- Имя игрока для чата: получить из текущего `ServerPlayer`, соответствующего UUID владельца. Если владелец недоступен, не придумывать ник и не формировать адресованную ему реплику.
- Для одиночного мира первоначально достаточно одного владельца и одного компаньона. Структуру состояния строить через UUID, чтобы расширение на несколько игроков позже не требовало полного переписывания мода.
- UUID компаньона также сохранять. Не затрагивать обычных куриц или иных случайных мобов.
- Конфиг в будущем: `companionName`, `entityType`, `maxHealth`, `ownerUuid` (сохраняемый идентификатор, обычно задаётся при создании), `ollamaModel`, `ollamaUrl`, интервалы обновлений и лимиты чата.
- Для MVP достаточно имени «Марк», типа `minecraft:chicken`, 4 HP, UUID владельца из команды.

## 5. Начальный класс MarkBrain

Имеется отдельный файл `src/main/java/dev/markai/brain/MarkBrain.java`, который нужно поместить в Fabric-проект. Ключевое изменение - `playerName` и `distanceToPlayer`, никаких `distanceToDenis()`.

```java
package dev.markai.brain;

public final class MarkBrain {
    private MarkBrain() {}

    public record WorldState(
        String playerName,
        double distanceToPlayer,
        double enemyDistance,
        int health
    ) {}

    public record Decision(String action, String message) {}

    public static Decision think(WorldState world) {
        if (world == null) {
            throw new IllegalArgumentException("WorldState must not be null");
        }

        String name = world.playerName() == null || world.playerName().isBlank()
            ? "друг"
            : world.playerName();

        if (world.enemyDistance() < 6.0) {
            return new Decision("FLEE", name + ", БЛЯ, СПАСАЙ!");
        }

        if (world.distanceToPlayer() > 4.0) {
            return new Decision("FOLLOW", name + ", подожди меня!");
        }

        return new Decision("IDLE", "Чё делаем, " + name + "?");
    }
}
```

Правила получения данных:

- `playerName`: реальный игровой ник игрока, идентифицированного как владелец; строка для отображения, **не** ключ идентификации.
- `distanceToPlayer`: дистанция от компаньона до владельца в блоках.
- `enemyDistance`: дистанция до ближайшего опасного враждебного моба, если он существует; если врагов нет - `Double.POSITIVE_INFINITY`.
- `health`: здоровье компаньона в HP, **не количество сердечек**; 4 HP = 2 сердца. Для будущих реализаций с дробным здоровьем можно сменить тип на `float` / `double` во всём проекте согласованно.
- `Decision.action`: пока `FLEE`, `FOLLOW`, `IDLE`; исполнитель обрабатывает только разрешённые варианты. Не исполнять произвольные команды из текста.
- Применять `think()` не каждый тик, а через разумный интервал или по событиям. Это временная детерминированная логика - после подключения Ollama её можно оставить как **безопасный fallback**.

## 6. Минимальные игровые команды

- `/mark spawn` - создать или восстановить компаньона вызывающего игрока, не плодить дубликаты.
- `/mark follow` - следовать за текущим владельцем.
- `/mark stay` - оставаться на месте.
- `/mark status` - показать UUID и параметры компаньона, состояние логики и владельца.
- `/mark respawn` - по необходимости повторно создать погибшего компаньона.

Команды адресованы вызывающему игроку и его мобу, а не глобально захардкоженному нику. Если команды требуют включённых читов / прав, прямо описать это в README. Не менять обычные игровые сообщения без необходимости.

## 7. Подключение локального ИИ (второй этап)

Схема:

```text
Fabric логический сервер
  -> получить UUID владельца и реальный ник
  -> WorldObserver (состояние конкретного компаньона и мира)
  -> асинхронный HTTP к Ollama (127.0.0.1:11434)
  -> проверить структурированный JSON-ответ
  -> исполнить разрешённое действие на игровом потоке
  -> отправить текст в чат, если уместно
```

Пример запроса к модели:

```json
{
  "companion": {"name": "Марк", "type": "minecraft:chicken", "health": 4},
  "player": {"name": "Player123", "distance_blocks": 5.5},
  "nearby_hostiles": [{"type": "zombie", "distance_blocks": 7.0}],
  "last_player_message": "Марк, сюда!"
}
```

`Player123` - **пример произвольного ника**, подставляемого из игры, а не константа. Ответ:

```json
{"action": "follow", "say": "Player123, иду!"}
```

- Не блокировать игровые тики ожиданием модели. HTTP на другом потоке, применение изменений - только на игровом серверном потоке.
- Пока LLM думает, моб может продолжать предыдущее безопасное действие или стоять.
- Допустимые решения ограничить: `follow`, `stay`, `flee`, `wander`, `look_at_player`, `say`, `idle`.
- Не выполнять из ответов нейросети произвольный Java-код, shell-команды или команды Minecraft.
- При ошибке Ollama, тайм-ауте, неверном JSON использовать `MarkBrain.think()` или безопасное бездействие.
- Ограничить частоту сообщений, длину ответов и размер истории диалога. Впоследствии добавить простую память.
- Чат и игровые данные не отправлять во внешние сервисы.

## 8. Поведение и характер

- Марк - разговорчивый, но не спамящий компаньон, который знает, что у него всего 4 HP.
- Главная цель - сопровождать **своего владельца**, а не случайного ближайшего игрока.
- При опасности предпочитает убегать, а не драться.
- Говорит по-русски, коротко, живо, с юмором; умеренная ненормативная лексика допустима по ситуации.
- Может проявлять инициативу, если наблюдатель зафиксировал значимое событие.
- Не выдумывает игровые события, если `WorldObserver` их не передал.
- При отсутствии имени владельца не показывает буквальный текст `<ИМЯ>`.

## 9. План работ и критерии готовности

**Этап 1 - Fabric-мод без Ollama:**

1. Подтвердить фактическую среду Windows и JDK, выбрать корректный Fabric starter для Minecraft 26.3.
2. Создать рабочий Gradle-проект и подключить `MarkBrain.java`.
3. Создать/идентифицировать одну особую курицу, присвоить имя «Марк» и максимум 4 HP.
4. По UUID привязать её к вызвавшему `/mark spawn` игроку.
5. Реализовать `/mark follow`, `/mark stay`, `/mark status` и реакцию на угрозу.
6. Реально собрать мод, исправить ошибки, протестировать одиночную игру.
7. Написать README: установка Fabric, команды, сборка, диагностика.

**Этап 2 - локальная LLM:**

1. Настроить локальную Ollama и проверить `qwen3:8b` / `qwen3:4b`.
2. Реализовать асинхронный запрос и проверку JSON.
3. Научить компаньона понимать сообщения игрока и отвечать в игровой чат.
4. Соединить ответы LLM с игровыми действиями и безопасным fallback.

**Этап 3 - развитие:**

- Конфигурация имени, типа моба, здоровья, локальной модели и периодичности обращений.
- Память последних событий, автономные комментарии и дополнительное поведение.
- Возможная поддержка нескольких игроков и независимых компаньонов - **не нужна в первом прототипе**.

**Критерий готовности первого прототипа:** мир запускается с модом, `/mark spawn` создаёт курицу конкретного игрока, курица следует/останавливается/убегает, команды не требуют знать игровой ник заранее, игра не падает. Пока нет фактической сборки и игрового теста - не объявлять прототип готовым.
